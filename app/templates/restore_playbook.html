Full Instance Restore (Fastest Complete Path)

sudo systemctl stop gitea
cd /tmp
# pick latest backup from /backup/gitea
unzip /backup/gitea/<latest-backup.zip> -d gitea-restore

# restore into expected Gitea paths based on archive structure
# typical targets:
#   /var/lib/gitea/data
#   /var/lib/gitea/custom
#   database dump file

sudo systemctl start gitea

Restore order: stop service -> restore files/data/db -> start service -> validate login/repos.

Repo-Only Emergency Recovery

# If full restore is blocked, recover repositories first:
rsync -a <android-mirror-source>/ /var/lib/gitea/data/gitea-repositories/
sudo chown -R git:git /var/lib/gitea/data/gitea-repositories
sudo systemctl restart gitea

Repo-only recovery may not include full metadata (issues/users/settings) until full restore is done.

Verification After Restore

  • Gitea service starts and login works.
  • Expected repository count is present.
  • Key organizations are visible.
  • Open one or two critical repos and inspect recent commits.

Operational Notes

  • /usr/local/bin/gitea-backup.sh (local backup)
  • /usr/local/bin/gitea-sync-android.sh (manual Android sync)

Live operation status is available from the Quick Actions job cards and their status JSON files.

During incident response, trust the latest successful backup verification and health-check results before destructive restore steps.
